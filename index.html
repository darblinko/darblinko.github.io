Method

The projects below cover three domains. Each one applies the same five rules to the LLM components in it.

Models are measured before they are selected

  • golden-goose gates each eval run on retrieval recall, grounded-answer rate, citation recall and precision, sentence support and routing accuracy.
  • llm-trading-lab validates its screening model over 21 walk-forward folds and audits its features for look-ahead leaks.

Outputs carry provenance or an audit record

  • golden-goose keeps a hash-chained, append-only audit log and retrieves documents by revision as of a date.
  • llm-trading-lab records each prompt change as before, after, diff and rationale; 95.2% of the records have all four, and 74.7% state a falsifier.

Deterministic code owns what must be exact

  • golden-goose routes count and trace questions to SQL or graph queries instead of the model.
  • cypher-guard checks LLM-generated Cypher against tenant-scoping rules before it reaches the database.
  • obd-scanner blocks agent writes outside the project, raw serial-port access and secret-file reads with a pre-tool-use hook.

Agents are checked by other agents or by sandboxes

  • agent-controls runs a second coding agent as a reviewer at the end of every session, capped at two rounds, and confines Codex CLI to named directories with bubblewrap.
  • llm-trading-lab ships two review apps that replay a synthetic two-agent trading session, in which an entry needs both agents to agree.

Negative results are recorded

  • llm-trading-lab reports the strategies that showed no edge and the setup families that failed their first validation stage.
