Evaluating an agentic RAG system for regulatory audit support

The golden-goose eval battery fails a run when any of 7 metric gates, a non-leakage check or 5 coverage floors is missed. On a synthetic quality system for a fictional infusion pump, the recorded seed-42 run passed all of them, with recall@10 of 94.4% and routing accuracy of 98.1% (212 of 216 questions). Its 100% grounded answer rate was measured with a fake extractive generator, so it tests the citation path and does not measure a hosted model's answers.

Scope: what the system is for and what was measured

golden-goose is a LangGraph agent that answers questions about a medical device quality management system. It uses hybrid retrieval in Qdrant, a Neo4j graph and a Postgres record warehouse, and each answer cites document ID, revision and page. Its project page describes the system and the repository holds the code. This article covers the eval battery: what each metric computes, how the gates were set, what the one recorded run scored, and which architecture decision records (ADRs) refer to the measurement.

The intended-use statement scopes the system to decision support during regulatory audit preparation and live audit response. A trained user opens the cited revision and confirms each claim before relying on it. A human writes the response to the auditor. The system is read-only over quality records and is not a 21 CFR Part 11 electronic record or signature system.

All evaluation data is synthetic. The repository generates a QMS for the fictional Halvern Medical infusion pump family, together with a golden question set and seeded defects. No figure in this article was measured on a real company's documents.

gg-eval battery builds the same dependency stack as the API, forces external tools (openFDA, eCFR and the others) offline, and runs four evals over one QA file. The retrieval, answer and noise evals use only questions whose evidence includes a retrievable document key. The others are skipped and listed with a reason, so a skipped question cannot raise a score. The routing eval uses every question, because count questions answered from the warehouse are the ones routing has to get right.

CI runs the battery on the 30-question smoke set in the integration job for each push and pull request. A scheduled nightly workflow rebuilds the corpus from the seed, ingests, derives and runs the battery on the full golden set. It writes the JSONL history and the trend dashboard before the gate decision, so a failing night still appears in the trend.

What each metric computes

ADR 0013 replaced the ranx library with local code for recall@k, MRR and nDCG@k. ranx depends on numba, and its install was fragile on Python 3.13; unit tests against hand-computed values fix the formulas so a refactor cannot change what a gate means. The answer, routing and noise metrics are local code as well. known-limitations.md records that DeepEval and RAGAS are absent and that the choice is to be revisited if a regulator or downstream consumer requires a named, externally recognized framework.

Sentence supportFor each sentence with at least 4 distinct content tokens: the share of its tokens found in the source its [n] marker cites, or in the whole evidence window when it has no marker. The share is multiplied by 0.2 when the sentence states a number the source lacks, and by 0.2 when its negation differs from a source that covers 60% or more of it. Routing accuracy1 if the regex router's choice, or the default route record when no regex matches, is in the question's acceptable routes as emitted by the generator.All questions (216)
Noise degradationRecall of the clean top 10 minus recall after the reranker reorders the clean candidates plus 5 chunks retrieved for other questions. Distractor intrusion, the share of the reranked top 10 taken by distractors, is reported without a gate.Questions that received distractors
Non-leakageAny document, or document at a given revision, that the question lists as must-exclude and that appears in the retrieved chunks.Scored questions

Two rules in the table stop a metric from passing for the wrong reason. Citation and support scores average over grounded answers only, because an insufficient-evidence verdict has no citations to score and is already counted once through the grounded rate. Support scores each sentence against the source its own marker cites. A correct sentence attached to the wrong document therefore scores low even when the right document is elsewhere in the evidence window, and a unit test asserts this case.

How the gates were set

The gate values below are the defaults of BatteryThresholds in the code. The rationale column quotes the repository. ADR 0019 states that its gates were locked after a calibration run on the full golden set and gives the calibration figures; it does not give the revision or seed of that run.

The coverage floors guard the denominators. Each metric gate averages over the questions that survive selection, so a QA set that lost questions would leave every gate green. For the full golden set the floors are at least 200 questions, at least 180 scored for retrieval, a skip rate of at most 8%, at least 5 questions per pattern and at least 150 questions tested against distractors. An optional fingerprint pin on the QA structure is not set.

The 4 misroutes, QA-0206 to QA-0209, are governance and clinical questions that ask for a CAPA count within a management review period. The count phrasing sends them to the aggregate tool, and the routing table excludes aggregate for this pattern because the answer must come from the review record. A comment in the routing eval states that the gate is not relaxed to hide this misroute. By computation from the gate, the 90% floor would still pass with up to 21 misroutes out of 216.

No per-pattern recall gate exists. Supplier questions reach 14.3% recall@10 over 7 questions and seeded defect discovery 71.4% over 7, while the 80% gate applies to the mean over 207. The project page plots recall by pattern.

What the fake generator means for the grounded number

With no LLM key the generate node does not call a model. It returns a header line and, for at most 2 internal evidence parents, the citation label and the first 240 characters of the parent's text followed by a [n] marker. A tool result is returned whole with [1]. The verifier then checks that the answer carries at least one marker that points at an evidence parent. It does not judge entailment: it records fake llm: entailment not evaluated and returns grounded.

A grounded rate of 100% under these conditions shows that each of the 207 scored questions reached at least one evidence parent with a usable revision and that the answer carried a resolvable citation. It does not measure whether a hosted model's answers are supported by their sources. docs/results/ holds only the fake-provider run.

The fake also shapes the other answer metrics. The following points are inferences from the code, not separate measurements:

  • Because the fake cites at most 2 internal parents, citation precision measures whether the top 2 parents in the generation window are golden evidence, and citation recall cannot reach 1.0 for a question with more than 2 evidence documents.
  • The fake quotes source text, so its sentences contain no invented content. The 58.9% support score then comes from the text around and inside the quotes: the header line, the citation labels, the 240-character clips and sentence fragments scored against one cited source. The report has no per-answer breakdown that would confirm this.
  • Dense vectors under fakes are SHA-256 pseudo-vectors and the fake reranker scores IDF-weighted token overlap. Recall@10 of 94.4% therefore measures the BM25 branch and a lexical reranker, and the noise result measures the lexical stand-in in place of a cross-encoder.

Limits of this result

  • Synthetic corpus. The generator that writes the documents also writes the golden questions. The README states that results do not transfer to a real QMS without a new golden set. Inference: questions and documents from one generator share identifiers and phrasing, which favours the lexical retrieval path measured here.
  • Fake providers. A hosted LLM's answers, the LLM router, dense retrieval and a cross-encoder reranker are not measured. The routing eval scores the regex layer and the default route even when keys are present.
  • One seed, one run. No variance across seeds or reruns is recorded, and ADR 0013 gives up significance testing. The nightly trend history is best effort: the traceability matrix notes that concurrent runs can fork it and cache eviction resets it.
  • Lexical support. Sentence support measures token overlap with the cited source. A strict xfail test records that it cannot detect an actor swap, where the approver and the approved plan exchange places in the same sentence.
  • No per-pattern gate. Supplier recall is 14.3% over 7 questions while the mean passes.
  • Recorded discrepancy between ADR 0019 and the code. This article uses the code values.
    • ADR 0019 says citation precision is tracked and not gated. BatteryThresholds gates citation precision and citation recall at 0.5 each. Requirement R-01 in the traceability matrix agrees with the code.
    • ADR 0019 says the noise gate is on nDCG degradation. The code gates mean recall degradation. Requirement R-05 in the traceability matrix agrees with the code.
    • ADR 0019 describes support as the best coverage in any evidence text. The answer eval scores each sentence against the source it cites.
    • ADR 0019 lists 5 gates. The code applies 7 metric gates, the non-leakage check and the coverage floors.
    The ADR's calibration figures for support (0.830) and routing (1.000) also differ from the seed-42 values (0.589 and 0.981). The repository does not record when the calibration ran or what changed after it.
  • Scope. The system is read-only decision support. Its answers point to controlled documents and do not replace them, and the eval does not test the user's verification step.
